# Traffic Calibration

This skill ingests historical GPS telemetry generated by the fleet-intelligence skills, joins it with the ORS travel-time prediction at the time of the trip, and learns a multiplicative speed factor per (profile, region, hour-of-day, road-class). The result is a `CALIBRATED_DURATION(profile, distance_m, hour_of_day, road_class, region)` SQL function that downstream demos call instead of the raw ORS duration.

This is the implementation skeleton from issue #64. The framing, dynamic tables, and evaluation methodology are pinned here so the build-out is self-contained.

## Required Privileges

| Privilege | Object |
|---|---|
| USAGE | Database `OPENROUTESERVICE_APP`, `FLEET_INTELLIGENCE` |
| USAGE | Schema `FLEET_INTELLIGENCE.CORE`, `OPENROUTESERVICE_APP.CORE` |
| CREATE SCHEMA, CREATE DYNAMIC TABLE, CREATE FUNCTION, CREATE PROCEDURE | `FLEET_INTELLIGENCE` |
| USAGE | Warehouse `ROUTING_ANALYTICS` |
| SELECT | `FLEET_INTELLIGENCE.CORE.FACT_VEHICLE_TELEMETRY` (or its `V_*_CURRENT` view) |

ACCOUNTADMIN is not required.

## Configuration

| Parameter | Default | Description |
|---|---|---|
| `CALIBRATION_REGION` | active region | Region to calibrate (must already be provisioned via `build-routing-solution`) |
| `CALIBRATION_PROFILES` | `driving-car,driving-hgv` | Comma-separated ORS profiles to calibrate |
| `CALIBRATION_WINDOW_DAYS` | 14 | Lookback window of telemetry data |
| `CALIBRATION_MIN_TRIPS_PER_BUCKET` | 30 | Minimum observed trips before publishing a speed factor for a bucket |
| `CALIBRATION_TARGET_MAPE_REDUCTION_PCT` | 10 | Eval target: at least this much MAPE reduction on the hold-out |

## Workflow

### Step 1 — Set the session query tag

```sql
ALTER SESSION SET query_tag = '{"origin":"sf_sit-is-fleet","name":"oss-traffic-calibration","version":{"major":1,"minor":0},"attributes":{"is_quickstart":1,"source":"sql"}}';
```

### Step 2 — Verify prerequisites

```sql
-- ORS must be running for the target region
SHOW SERVICES IN DATABASE OPENROUTESERVICE_APP;

-- Telemetry must exist (≥ N trips for the calibration window)
SELECT COUNT(*) AS TRIP_ROWS
FROM SYNTHETIC_DATASETS.UNIFIED.V_FACT_TRIPS_CURRENT
WHERE TRIP_END_TIME >= DATEADD(day, -14, SYSDATE());
```

### Step 3 — Deploy the dynamic tables and calibration function

Run the SQL in [`references/dynamic-tables.sql`](references/dynamic-tables.sql). It creates:

- `FLEET_INTELLIGENCE.TRAFFIC.OBSERVED_TRIPS` — dynamic table over the telemetry, materializing one row per (trip, profile) with the observed travel time and the ORS-predicted travel time at the trip's start hour.
- `FLEET_INTELLIGENCE.TRAFFIC.SPEED_FACTORS` — dynamic table aggregating `OBSERVED_TRIPS` into one row per (profile, region, hour_of_day, road_class) with the median observed / predicted ratio.
- `FLEET_INTELLIGENCE.TRAFFIC.CALIBRATED_DURATION` — scalar UDF that multiplies the raw ORS duration by the calibrated speed factor (falls back to 1.0 when no factor is available for the bucket).

### Step 4 — Run the evaluation notebook

Upload [`assets/traffic_calibration_eval.ipynb`](assets/traffic_calibration_eval.ipynb) to a Snowsight notebook bound to `ROUTING_ANALYTICS`. The notebook:

1. Splits `OBSERVED_TRIPS` into 80% train / 20% hold-out by trip-start timestamp.
2. Computes baseline MAPE: `mean(|ors_duration - observed_duration| / observed_duration)`.
3. Computes calibrated MAPE using `CALIBRATED_DURATION`.
4. Asserts MAPE reduction ≥ `CALIBRATION_TARGET_MAPE_REDUCTION_PCT` (default 10).

### Step 5 — Wire the calibrated function into demos

Each demo that surfaces ETAs (fleet-intelligence-taxis, fleet-intelligence-food-delivery, route-optimization, route-deviation) should call `FLEET_INTELLIGENCE.TRAFFIC.CALIBRATED_DURATION(profile, distance_m, hour_of_day, road_class, region)` instead of the raw ORS duration. The function returns the raw duration when no factor is available, so a demo running before this skill has been deployed continues to work.

## Cleanup

```sql
DROP FUNCTION IF EXISTS FLEET_INTELLIGENCE.TRAFFIC.CALIBRATED_DURATION(VARCHAR, FLOAT, INTEGER, VARCHAR, VARCHAR);
DROP DYNAMIC TABLE IF EXISTS FLEET_INTELLIGENCE.TRAFFIC.SPEED_FACTORS;
DROP DYNAMIC TABLE IF EXISTS FLEET_INTELLIGENCE.TRAFFIC.OBSERVED_TRIPS;
DROP SCHEMA IF EXISTS FLEET_INTELLIGENCE.TRAFFIC;
```

## Evaluation rubric

Pass criteria (see step 4):

- Baseline MAPE captured (no calibration).
- Calibrated MAPE ≥ 10% lower than baseline on the held-out window.
- At least 50% of (profile, hour_of_day, road_class) buckets have a published factor (covers the most-trafficked combinations).

If any criterion fails the deploy is incomplete; iterate on the bucket definitions in `references/dynamic-tables.sql` (try coarser/finer time bins, add `dow` if hour_of_day alone is too noisy).
