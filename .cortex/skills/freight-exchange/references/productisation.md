# Freight Exchange — Productisation Notes

The deployed demo runs on synthetic per-preset data generated by Data Studio. To take this to production for a real freight carrier, here is what changes by phase.

## Phase A/B (shipped)

What you get out of the box: a sortable grid + map of synthesized offers (~300 per preset) with trust + market-rate badges. This is the "looks like Timocom" + "the trust intelligence Timocom charges for" combo.

## Phase C (next: action engine)

Adds the dispatcher's day-to-day workflow on top of the read-only browse experience.

### Saved searches + Snowflake Alerts -> SSE toasts

```sql
CREATE TABLE FLEET_INTELLIGENCE.MARKETPLACE.SAVED_SEARCHES (
  SEARCH_ID VARCHAR DEFAULT UUID_STRING() PRIMARY KEY,
  DISPATCHER_ID VARCHAR, NAME VARCHAR, FILTERS VARIANT,
  ALERT_ENABLED BOOLEAN, CREATED_AT TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP()
);

-- One Snowflake Alert per saved search; fires when a new offer matches.
CREATE ALERT FLEET_INTELLIGENCE.MARKETPLACE.ALERT_<search_id>
  WAREHOUSE = ROUTING_ANALYTICS
  SCHEDULE = '5 MINUTE'
  IF (EXISTS (SELECT 1 FROM VW_OFFERS WHERE <FILTERS> AND POSTED_AT > DATEADD(minute, -5, CURRENT_TIMESTAMP())))
  THEN CALL SNOWFLAKE.NOTIFICATION.NOTIFY( ... );
```

Notification payloads land on a webhook served by an Express route in the control app, which fans them out via SSE to connected dispatcher browsers (toast in the page header).

### Reverse posting (free truck / load offer)

```sql
CREATE TABLE POSTED_TRUCKS (
  POSTED_ID VARCHAR DEFAULT UUID_STRING() PRIMARY KEY,
  TRAILER_ID VARCHAR, REGION VARCHAR, AVAILABLE_FROM TIMESTAMP_NTZ,
  EQUIPMENT VARCHAR, ASKING_USD NUMBER, STATUS VARCHAR,
  CREATED_AT TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP()
);

CREATE TABLE POSTED_LOADS (
  POSTED_ID VARCHAR DEFAULT UUID_STRING() PRIMARY KEY,
  LOADER_ID VARCHAR, PICKUP_GEOG GEOGRAPHY, DROPOFF_GEOG GEOGRAPHY,
  PICKUP_FROM_TS TIMESTAMP_NTZ, EQUIPMENT VARCHAR, ASKING_USD NUMBER, STATUS VARCHAR,
  CREATED_AT TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP()
);
```

Both feed back into the candidate pool VW_OFFER_ENRICHED via UNION ALL so the page renders self-posted offers identically.

### Chat threads + counter-bids

```sql
CREATE TABLE OFFER_THREADS  (THREAD_ID, OFFER_ID, OPENED_BY, STATUS, ...);
CREATE TABLE OFFER_MESSAGES (THREAD_ID, SENDER, BODY, AI_DRAFTED BOOLEAN, TS);
CREATE TABLE OFFER_BIDS     (BID_ID, OFFER_ID, DISPATCHER_ID, BID_USD, STATUS);
```

Cortex Complete drafts the opening message; counter-bid acceptance writes a `PROPOSAL_DECISIONS` row (same audit table backload-matching uses, with a new `SOURCE_PAGE` column to distinguish origin).

## Phase D (compliance + scale)

### Document workflow (CMR / POD / ADR certs)

```sql
CREATE STAGE OFFER_DOCS;

CREATE TABLE OFFER_DOCS_INDEX AS
SELECT
  OFFER_ID,
  RELATIVE_PATH,
  AI_PARSE_DOCUMENT(BUILD_SCOPED_FILE_URL(@OFFER_DOCS, RELATIVE_PATH)) AS PARSED
FROM DIRECTORY(@OFFER_DOCS);
```

Front-end uploads to the stage; AI_PARSE_DOCUMENT extracts weight, LDM, ADR class, signatures.

### Cross-border flags

Pre-compute via `ST_INTERSECTS` between offer LINESTRING and `OPENROUTESERVICE_APP.CORE.REGION_CATALOG.BOUNDARY` of neighbouring countries. Cache on the offer row.

### Round-trip toggle

Solver already supports it (`vehicles[].steps` chain with a constraint on returning near `vehicle.end`). UI adds a toggle, payload tweaks the VROOM challenge.

### Tariff calculator

Standalone widget — calls Cortex Complete with `RATE_INDEX` percentile + lane + equipment as the prompt context, returns "suggested 1.42 USD/km, market p50 1.38 USD/km".

## Live exchange API integrations (productisation)

For a real DHL Freight install, replace the per-preset generator with Snowpipe Streaming feeds from the four exchanges:

```
[TIMOCOM API]   -> Snowpipe Streaming -> FACT_FREIGHT_OFFERS_RAW
[WTRANSNET]     -> Snowpipe Streaming -> ...
[TELEROUTE]     -> Snowpipe Streaming -> ...
[B2P]           -> Snowpipe Streaming -> ...
                                       -> Dynamic Table FACT_FREIGHT_OFFERS_ENRICHED (5 min lag)
                                          - normalize source-specific fields
                                          - AI_CLASSIFY for cargo category
                                          - regex flags for ADR / reefer / FTL/LTL
```

Snowpark Container Services worker per exchange (4 services) authenticates, polls, normalizes, pushes rows. The page is unchanged; it still reads `VW_OFFER_ENRICHED`.

## Real partner trust feed

For production:

1. Replace `DIM_PARTNERS.CREDIT_SCORE` with a daily refresh from a credit-bureau API (Dun & Bradstreet, GLEIF for LEI, KredittInfo, Coface for EU SMB risk).
2. Replace `KYC_STATUS` with a sanctions-list cross-check (OFAC, EU, UK consolidated lists) via a Snowflake Marketplace listing.
3. Replace `BLACKLIST_FLAG` with a per-tenant blacklist table that operations can mutate.
