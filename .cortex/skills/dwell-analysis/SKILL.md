# Deploy Dwell & Congestion Analysis

8 Dynamic Tables transforming telemetry → dwell sessions → congestion heatmaps + SLA alerts.

## Prerequisites

- `SYNTHETIC_DATASETS.UNIFIED.FACT_VEHICLE_TELEMETRY` with POINT_GEOM, STATUS, LOCATION_ID columns
- `SYNTHETIC_DATASETS.UNIFIED.DIM_POIS` with POINT_GEOM column
- `ROUTING_ANALYTICS` warehouse

## Workflow

### Step 1: Execute Pipeline

Run `references/sql-pipeline.sql` statement-by-statement. Creates:

| Dynamic Table | Purpose | Key Columns for React App |
|---|---|---|
| `DT_STATE_CHANGES` | LiveOperations | VEHICLE_ID, STATUS, POINT_GEOM, TS, IS_STATE_CHANGE |
| `DT_DWELL_EVENTS` | Session detection | SESSION_ID, VEHICLE_ID, DWELL_START, DWELL_MINUTES, LOCATION_ID |
| `DT_DWELL_ENRICHED` | POI-enriched sessions | SESSION_ID, SESSION_START, SESSION_END, LOCATION_NAME, AVG_POINT, STATUS |
| `DT_H3_CONGESTION` | CongestionMap | **H3_CELL_R7**, **HOUR_BUCKET**, **SESSION_COUNT**, AVG_DWELL_MIN |
| `DT_SLA_ALERTS` | SLAAlerts | **SLA_STATUS**, SESSION_ID, LOCATION_NAME, DWELL_MINUTES, **WARNING_MINUTES** |
| `DT_FACILITY_UTILIZATION` | FacilityUtilization | **LOCATION_NAME**, **FACILITY_TYPE**, **TOTAL_SESSIONS** |
| `DT_DAILY_TRENDS` | DwellOverview | **TREND_DATE**, **TOTAL_SESSIONS**, ACTIVE_VEHICLES |
| `DT_DRIVER_DWELL_SUMMARY` | DriverPerformance | VEHICLE_ID, TOTAL_DWELL_SESSIONS, SLA_BREACH_COUNT |

> **CRITICAL:** Column names in **bold** must match EXACTLY — the React components query these by name.

### Step 2: Refresh

```sql
ALTER DYNAMIC TABLE FLEET_INTELLIGENCE.DWELL_ANALYSIS.DT_DWELL_EVENTS REFRESH;
ALTER DYNAMIC TABLE FLEET_INTELLIGENCE.DWELL_ANALYSIS.DT_DWELL_ENRICHED REFRESH;
ALTER DYNAMIC TABLE FLEET_INTELLIGENCE.DWELL_ANALYSIS.DT_H3_CONGESTION REFRESH;
ALTER DYNAMIC TABLE FLEET_INTELLIGENCE.DWELL_ANALYSIS.DT_SLA_ALERTS REFRESH;
ALTER DYNAMIC TABLE FLEET_INTELLIGENCE.DWELL_ANALYSIS.DT_FACILITY_UTILIZATION REFRESH;
ALTER DYNAMIC TABLE FLEET_INTELLIGENCE.DWELL_ANALYSIS.DT_DAILY_TRENDS REFRESH;
ALTER DYNAMIC TABLE FLEET_INTELLIGENCE.DWELL_ANALYSIS.DT_DRIVER_DWELL_SUMMARY REFRESH;
```

### Step 3: Verify

```sql
SELECT 'DT_DWELL_EVENTS' AS DT, COUNT(*) AS CNT FROM FLEET_INTELLIGENCE.DWELL_ANALYSIS.DT_DWELL_EVENTS
UNION ALL SELECT 'DT_H3_CONGESTION', COUNT(*) FROM FLEET_INTELLIGENCE.DWELL_ANALYSIS.DT_H3_CONGESTION
UNION ALL SELECT 'DT_SLA_ALERTS', COUNT(*) FROM FLEET_INTELLIGENCE.DWELL_ANALYSIS.DT_SLA_ALERTS;
```

Expected: DT_DWELL_EVENTS 6K+, DT_H3_CONGESTION 1K+, DT_SLA_ALERTS 3K+.

## Key Design Decisions

1. **Status filter:** `WHERE STATUS IN ('DWELL_ORIGIN', 'DWELL_DESTINATION', 'IDLE')` — NOT `'stopped'`
2. **Grouping:** BY `VEHICLE_ID, TRIP_ID, LOCATION_ID` — joins DIM_POIS by LOCATION_ID for proper names
3. **H3 resolution 7** for congestion (city-block level granularity)
4. **SLA_THRESHOLDS:** Must use UPPERCASE location types (`'RESTAURANT'`, `'DWELL_ORIGIN'`, etc.)
5. **ISOCHRONES ?::INT cast:** Same pattern applies to any DT that calls ORS functions
