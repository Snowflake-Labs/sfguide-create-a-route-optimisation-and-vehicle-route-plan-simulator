## Friction points

### F2 (BLOCKER → fixed): `ORS_LIMIT_DEFAULTS()` declared `RETURNS VARIANT` but returns `OBJECT`
- **Step:** A2 (deploy). New function from commit `3cc02a0`.
- **Error:** `090207 (42601): Declared return type 'VARIANT' is incompatible with actual return type 'OBJECT'` - `OBJECT_CONSTRUCT(...)` is typed `OBJECT`.
- **Impact:** `snow sql -f` halts on first error, so every object after line ~1359 (the new `WRITE_ORS_CONFIG`, `APPLY_ORS_LIMITS`, `DOWNSIZE_REGION_AFTER_BUILD`) was **not** applied - silent partial deploy (only `create_region_ors_service` and earlier objects updated).
- **Resolution:** Source fix - cast body to `OBJECT_CONSTRUCT(...)::VARIANT`. Redeploy clean (33-34 objects).
- **Recommendation:** This is a latent regression that breaks any fresh install. The fix is committed. Consider a deploy-time compile check in CI for the SQL modules.

### F4 (BLOCKER → fixed): `LIST` graph probe unsupported inside `EXECUTE AS OWNER` procs
- **Step:** A7 (downsize). Affects `DOWNSIZE_REGION_AFTER_BUILD` AND `create_region_ors_service`.
- **Symptom:** `DOWNSIZE_REGION_AFTER_BUILD('Europe','L')` returned "Refusing to downsize Europe: no graph files found on stage" even though 29 graph files + `_BUILD_OK` were present.
- **Root cause:** Both procs probed graphs via `EXECUTE IMMEDIATE 'LIST @stage/region/'; SELECT COUNT(*) FROM TABLE(RESULT_SCAN(LAST_QUERY_ID()))`. Inside owner-rights procs this raises `Unsupported statement type 'LIST_FILES'`, caught by `EXCEPTION WHEN OTHER`, forcing `graph_file_count=0`. The codebase already documents this in `GRAPHS_ARTIFACT_COMPLETE` ("LIST is not callable inside SQL procs") and uses `DIRECTORY()` there.
- **Hidden second effect:** the same broken probe in `create_region_ors_service` drives the **runtime-family-reuse override** (`has_build_ok OR graph_file_count > 0`). With it always 0, the e1cc4b3 stickiness was inert - a re-provision/resume would re-resolve the large build family instead of the stored runtime family.
- **Resolution:** Source fix - replaced both `LIST`/`RESULT_SCAN` probes with `ALTER STAGE ... REFRESH` + `SELECT COUNT(*) ... FROM DIRECTORY(@stage) WHERE RELATIVE_PATH ILIKE :region || '/%'` (and `BOOLOR_AGG(... ILIKE :region||'/%_BUILD_OK%')` for the build_ok flag). Re-ran downsize: succeeded, Europe landed on HIGHMEM_X64_M, 29 graphs reused, `service_ready=true`.
- **Recommendation:** Audit the repo for any other `LIST`+`RESULT_SCAN` inside `EXECUTE AS OWNER` procs; standardize on `DIRECTORY()`.

### F1 (WARNING): `run_sql_module.sh` misses snow CLI box-drawn errors
- **Step:** A2. The wrapper greps `^(Error|[0-9]{6} \()`, but snow CLI renders errors inside a Unicode box (`│ 090207 (42601): ...`), so the regex never matches and the wrapper reports success on a failed module.
- **Resolution (this run):** Bypassed the wrapper - ran `snow sql -c TIB -f ...` directly and grepped the log myself; verified object-by-object.
