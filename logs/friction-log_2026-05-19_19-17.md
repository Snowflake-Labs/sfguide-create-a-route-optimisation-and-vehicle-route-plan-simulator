## Friction Points

### F1 (REGRESSION) — `03_region_management.sql` aborts at idempotent `ALTER TABLE ADD COLUMN IF NOT EXISTS IS_DEFAULT`

- **Symptom:** `snow sql -f` of module 3 stops at line 693 with `002028 (42601): SQL compilation error: ambiguous column name 'IS_DEFAULT'`. The CREATE TABLE on lines 671–690 already defines `IS_DEFAULT BOOLEAN DEFAULT FALSE` as part of the initial schema, then the immediately-following idempotent migration tries to add the same column with `ADD COLUMN IF NOT EXISTS`. Snowflake currently raises *ambiguous column name* instead of treating the IF NOT EXISTS as a no-op.
- **Impact:** Catastrophic on a fresh install. `snow sql -f` continues past the error in stdout but the session-scoped DDL state means the BOOTSTRAP_DEFAULT_REGION CALL at the tail of the file (line 2339) — which is what creates `ORS_SERVICE_SANFRANCISCO` and `VROOM_SERVICE_SANFRANCISCO` — never runs. After the broken first pass, the install still reported `OK: 03_region_management.sql` because the orchestrator wrapper `run_sql_module.sh` is invoked through `… | tail -8 || …` in the for-loop and `tail` always exits 0, masking the wrapper's exit-2. So the loop happily continued into modules 04, 05, 06 even though the SF service had not been created. Symptom: `SHOW SERVICES IN DATABASE OPENROUTESERVICE_APP` returned only 3 services; `REGION_ORS_MAP` was empty.
- **Resolution applied this run:** Commented out line 693 in `.cortex/skills/build-routing-solution/openrouteservice_app/app/modules/03_region_management.sql` (the redundant `ALTER TABLE … ADD COLUMN IF NOT EXISTS IS_DEFAULT`). Re-ran the module. BOOTSTRAP_DEFAULT_REGION succeeded; both SF services were created; SF graph built successfully (READY at 17:31).
- **Root cause:** Two issues stacked:
  1. The migration ALTER is unnecessary because every fresh install creates the table with `IS_DEFAULT` already in the schema. The comment on line 692 says "Idempotent migration for installs created before IS_DEFAULT existed" — but that pre-IS_DEFAULT schema no longer ships, so the ALTER is dead code that can only ever be a no-op (or, in this Snowflake version, a hard error).
  2. The deploy harness silently swallows per-module SQL errors because of the `… | tail -8 || …` pattern in the `for m in …; do` loop. `set -o pipefail` is **not** set, and `tail -8` always succeeds, so the wrapper's exit-2 from grep'ing the `^Error` marker never propagates.
- **Recommendations to prevent regression:**
  1. **(Skill change)** Delete lines 692-693 of `03_region_management.sql`. The CREATE TABLE already includes `IS_DEFAULT`; any pre-IS_DEFAULT installs are 12+ months old and can be migrated with a one-off run-once script, not a hot-path DDL. (I left the lines commented out in this run to preserve git history; recommend a dedicated `chore(build-routing-solution): drop redundant IS_DEFAULT migration` commit.)
  2. **(Harness change)** In SKILL.md Step 6 the for-loop should set `pipefail` or drop the `| tail -8` redirection so the wrapper's exit-2 actually aborts the chain. Concretely: `set -o pipefail; for m in …; do bash "$RUN_SQL" "$CONN" "$MODULES_DIR/$m" || exit 1; done` — note no `| tail -8`. Friction-log F1 from the 2026-05-19 prior run already documented an analogous failure (`REGION_CATALOG does not exist`); the wrapper added grep-for-error after that run, but the for-loop wrapping it was not updated, so the bug pattern repeats.
  3. **(Verification check)** After module 03 runs, the orchestrator should execute `SELECT COUNT(*) FROM OPENROUTESERVICE_APP.CORE.REGION_ORS_MAP;` — expected ≥ 1 (SanFrancisco). If 0, abort and instruct the user to investigate before letting modules 04-06 run against an empty registry. This is a one-line guard that would have failed loudly here.
