## Friction Points

### F1: `snow stage copy datasets/` lacked `--recursive` (BLOCKER)
- **Step:** 2 Data
- **Severity:** High
- **What happened:** `snow stage copy "$REPO_ROOT/datasets/" @...SEED_DATA_STAGE/ --overwrite` failed with `253006: Not a file but a directory: datasets/intro`. `datasets/` has nested subdirs (`intro/`, `metadata/`, `synthetic_ebikes/<table>/...`) the loader COPYs from by path.
- **Resolution:** Added `--recursive` + a `find … -name .DS_Store -delete` purge to the seed-copy in `scripts/install_fleet_apps.sh`.
- **Recommendation:** Keep `--recursive` permanently; add a post-copy `LIST @stage` row-count sanity check.

### F2: `--format=plain` is invalid in Snow CLI 3.x (BLOCKER, silent)
- **Step:** 1/2/5/8 (detection + URL extraction)
- **Severity:** High
- **What happened:** Snow CLI 3.16 only supports `TABLE/JSON/JSON_EXT/CSV`. Every `--format=plain` call returned an error swallowed by `2>/dev/null`, so `obj_exists()` always reported "absent" (infra never reused, data re-seeded every run), the account probe in `install_synapse_bundles.sh` returned empty (hard exit), and endpoint URL extraction yielded nothing.
- **Resolution:** Replaced all `--format=plain` with `--format=CSV` across `install_fleet_apps.sh`, `install_synapse_bundles.sh`, `deploy_fleet_sa_app.sh`, `deploy_fleet_admin_app.sh` (greps still match CSV cells).
- **Recommendation:** Never use `plain`; add a CLI-version assertion in preflight.

### F3: Engine module 01 created legacy `ors_control_app` service from an unstaged spec (BLOCKER)
- **Step:** 3 Engine (module load)
- **Severity:** High
- **What happened:** `01_core_infra.sql` ran `CREATE SERVICE … ors_control_app … SPECIFICATION_FILE='ors_control_app_service.yaml'`, but `install-fleet-apps` ships `fleet_sa_app`/`fleet_admin_app` instead and never stages that spec → `run_sql_module.sh` (fail-fast) aborted the whole engine provision.
- **Resolution:** Removed the legacy `ors_control_app` `CREATE SERVICE` block from `openrouteservice_app/app/modules/01_core_infra.sql` (Phase C - control app is superseded).
- **Recommendation:** Done; finish deleting all legacy control-app references.

### F4: Canonical loader aborted before `DIM_DATASETS` (BLOCKER)
- **Step:** 2 Data
- **Severity:** High
- **What happened:** `datasets/load-seed-data.sql` `ALTER TABLE FLEET_INTELLIGENCE.ROUTE_OPTIMIZATION.PLACES …` assumes the table exists (legacy control-app boot created it). On the agnostic path it doesn't, and `snow sql -f` is stop-on-first-error, so it never reached `DIM_DATASETS` (line 637) or the projection views.
- **Resolution:** Pre-create `FLEET_INTELLIGENCE.ROUTE_OPTIMIZATION` schema + `PLACES` + `LOOKUP` (DDL mirrored from engine module 15) in `scripts/seed_data.sql`, which runs before the loader.
- **Recommendation:** Long-term, make the canonical loader self-create the tables it ALTERs, or run it continue-on-error.

### F5: Pack installer resolved every pack under `packs/fleet/<name>` (BLOCKER)
- **Step:** 4 Packs
- **Severity:** High
- **What happened:** `_lib/install.py` hardcoded `FLEET_DIR/<name>`, but the `starter` pack lives at `packs/starter/` (separate `STARTER_APP` DB) → "no data-model/entity-mapping" + "setup.sql missing".
- **Resolution:** Added a `pack_dir()` resolver that prefers `packs/fleet/<name>` then falls back to `packs/<name>`.

### F6: Neutral substrate orphaned + wrong column (BLOCKER)
- **Step:** 4 Packs
- **Severity:** High
- **What happened:** The `starter` pack reads `SYNTHETIC_DATASETS.NEUTRAL.LOCATIONS/MOVEMENTS`, but `_substrate/neutral-sf.sql` was never applied by `install.py`. After wiring it in, its `ASSETS` view referenced `DIM_FLEET.VEHICLE_SUBTYPE`, which doesn't exist.
- **Resolution:** `install.py` now applies `_substrate/*.sql` before the pack loop; removed the nonexistent `VEHICLE_SUBTYPE` column from the substrate `ASSETS` view.

### F7: `V_*_CURRENT` projection views only created by the admin-app boot (BLOCKER)
- **Step:** 2/4
- **Severity:** High
- **What happened:** `unified_fleet` reads `SYNTHETIC_DATASETS.UNIFIED.V_*_CURRENT`, authored only in `fleet_admin_app/.../init.ts` (runs at container boot, step 8) - after the pack step (4).
- **Resolution:** New `scripts/projection_views.sql` (DDL mirrored from init.ts) creates the 5 agnostic views in the data step; wired into the orchestrator.

### F8: `DIM_VEHICLE_PROFILE` / `DIM_VEHICLE_DWELL_SLA` + DIM_FLEET asset columns only created by admin-app Studio TS (BLOCKER)
- **Step:** 2/4
- **Severity:** High
- **What happened:** `scoped_contract.sql` and `unified_fleet` need the catalog tables and DIM_FLEET asset columns (WEIGHT_TONS, HEIGHT_M, …, HAZMAT, VEHICLE_SUBTYPE) the Studio generator stamps - absent on the seed path (`invalid identifier 'F.WEIGHT_TONS'`).
- **Resolution:** New `scripts/vehicle_profile_catalog.sql` (SQL port of `vehicle-profile-catalog.ts`) creates+seeds both catalog tables and ADD COLUMN + stamps DIM_FLEET from the catalog (drops `V_DIM_FLEET_CURRENT` first since it's `SELECT f.*`). Runs before projection views.

### F9: Pack install aborted on first demo-data-dependent pack (ERROR)
- **Step:** 4 Packs
- **Severity:** Medium
- **What happened:** `dwell`/`route_deviation`/`catchment`/`route_optimization` read demo-skill objects (`FLEET_INTELLIGENCE.DWELL_ANALYSIS.CONFIG`, `ROUTE_DEVIATION.*`, `CATCHMENT.*`) not produced by the agnostic installer; `apply_pack` did `sys.exit` on the first failure.
- **Resolution:** Made `install.py` best-effort - failed packs are logged and skipped with a summary; the surfacing-gate (manifest `probe`) is the runtime authority. They surface after their demo skills seed data.
- **Recommendation:** Document that these 4 packs depend on the demo skills; consider an optional `--with-demos` that runs them.

### F10: Role ordering + app deploy scripts were redeploy-only (BLOCKER)
- **Step:** 4/8
- **Severity:** High
- **What happened:** (a) Pack `setup.sql` GRANTs to `FLEET_APP_*` roles, but roles are created in step 6 (after packs) → circular dep. (b) `deploy_fleet_sa_app.sh` only `ALTER`ed an existing service and assumed `FLEET_INTELLIGENCE.SYNAPSE_USER` schema + `FLEET_APP_STAGE` already existed - none do on a fresh account.
- **Resolution:** (a) Pre-create the 4 roles before packs (full binding stays in step 6). (b) Ported the admin script's first-create pattern into the SA script (`CREATE SCHEMA/STAGE IF NOT EXISTS` + `CREATE SERVICE IF NOT EXISTS` then ALTER).

### F11: App deploy guard blocks on dirty tree (INFO)
- **Step:** 8 Apps
- **Severity:** Low
- **What happened:** `deploy_*` refuse to run with uncommitted changes unless `ALLOW_DIRTY=1`. Expected (I had source fixes in flight); used `ALLOW_DIRTY=1`.
- **Recommendation:** None - guard is correct. Commit the 10 fixes (below) and re-run clean to validate.
