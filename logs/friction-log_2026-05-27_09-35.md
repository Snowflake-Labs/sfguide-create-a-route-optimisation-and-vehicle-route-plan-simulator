## Friction Points

### F1 — `SanFrancisco.osm.pbf` S3 upload timeout
- **Symptom:** `snow stage copy` of the 24MB PBF file timed out repeatedly with `ReadTimeoutError` (10s read timeout) against `sfc-in-ds1-39-customer-stage.s3.amazonaws.com`
- **Root cause:** Default `snow` connector socket timeout too short for this S3 endpoint from this network; ECONNRESET errors suggest unstable route to S3 India region bucket
- **Resolution:** Switched to Python snowflake-connector with `network_timeout=600, socket_timeout=600`; upload succeeded on good network
- **Recommendation:** Add a note to Step 4 recommending Python connector fallback for large files if `snow stage copy` times out. Alternatively, add a `PUT` SQL fallback command with `PARALLEL=4` as the documented first approach.

### F2 — Podman registry push token expiry mid-stream
- **Symptom:** `podman push --creds "0sessiontoken:$TOKEN"` failed with `Authentication Failure: [UNAUTHORIZED]` after pushing ~10/12 layers of `openrouteservice` (~424MB image)
- **Root cause:** SPCS registry bearer token expired during long push of large image (known SPCS registry bug)
- **Resolution:** Switched to `crane push` via `podman save | crane push` pattern per AGENTS.md recommendation; all 5 images pushed successfully
- **Recommendation:** Update `references/build-images.md` to use `crane` as the primary push method for all images, not just as a fallback. Add `brew install crane` to prerequisites. The `--creds` approach is unreliable for images >100MB.

### F3 — Missing `package-lock.json` for `ors_control_app` build
- **Symptom:** `podman build` of `ors_control_app` failed at `COPY package.json package-lock.json ./` — file not found
- **Root cause:** `package-lock.json` is gitignored and not present in the repo; `Dockerfile.runtime` `npm ci` step requires it
- **Resolution:** Ran `npm install --legacy-peer-deps` in the `ors_control_app` directory first to generate `package-lock.json`, then rebuild succeeded
- **Recommendation:** Add `cd ors_control_app && npm install --legacy-peer-deps` as a pre-build step in `references/build-images.md` for the `ors_control_app` image, regardless of architecture. Or commit `package-lock.json` to the repo.

### F4 — `snow` CLI not in PATH after `pip install`
- **Symptom:** `snow --version` returned NOT FOUND; `pip3 install snowflake-cli` installed to `/Users/pwate/anaconda3/bin/snow` but PATH was not updated
- **Root cause:** Anaconda Python's `bin/` not in shell PATH by default for non-interactive sessions
- **Resolution:** Used full path `/Users/pwate/anaconda3/bin/snow` in all subsequent commands
- **Recommendation:** Add a `which snow || pip3 install snowflake-cli && export PATH=...` check to the skill workflow prerequisites section.

### F5 — Overture Maps not available on demo account
- **Symptom:** `CALL SYSTEM$ACCEPT_LEGAL_TERMS(...)` returned "listing does not exist or not authorized" for all 3 Overture Maps listings
- **Root cause:** Demo account (`SFSEAPAC-DEMO_PWATE`) does not have access to these Marketplace listings
- **Resolution:** Skipped Overture Maps step; deployed seed-data-only demos (Food Delivery, Route Deviation, Dwell Analysis) instead
- **Recommendation:** Add a note in Step 7b that some demo accounts may not support `SYSTEM$ACCEPT_LEGAL_TERMS` and require manual Snowsight UI installation.
