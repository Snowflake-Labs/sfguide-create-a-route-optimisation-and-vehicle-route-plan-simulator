## Friction Points

### F1: App completion banner prints a placeholder instead of the endpoint URL

- **Step:** 7 apps (deploy_fleet_sa_app.sh / deploy_fleet_admin_app.sh) and the final installer summary.
- **Severity:** Low (cosmetic).
- **What happened:** Both app deploy summaries and the installer's final banner
  printed `url: https://Endpoints provisioning in progress... check back in a few minutes`
  instead of the resolved ingress URL. The endpoints resolve within ~1-2 min of
  service RESUME, but the deploy script queries `SHOW ENDPOINTS` immediately after
  RESUME, before SPCS finishes provisioning the public ingress, so the literal
  placeholder string returned by `ingress_url` is what gets printed.
- **Resolution (this run):** Re-queried `SHOW ENDPOINTS IN SERVICE ...` a couple
  of minutes later; both resolved cleanly:
  - SA app:    https://fvcmjncj-pm-fleet-test.snowflakecomputing.app
  - Admin app: https://jvcmjncj-pm-fleet-test.snowflakecomputing.app
  Both return HTTP 302 to the Snowflake OAuth login (expected for a gated SPCS app).
- **Recommendation (source fix, new-deployment-first):** In `[7/7] Resolve
  endpoint URL` of `deploy_fleet_sa_app.sh` and `deploy_fleet_admin_app.sh`, poll
  `SHOW ENDPOINTS` for up to ~90s (retry while `ingress_url` still contains
  "provisioning in progress") before printing, and fall back to a short note
  ("endpoint still provisioning; run SHOW ENDPOINTS in ~2 min") only on timeout.
  The installer's final summary reads the same values, so fixing the two deploy
  scripts fixes the banner too. Low priority - does not affect functionality.
