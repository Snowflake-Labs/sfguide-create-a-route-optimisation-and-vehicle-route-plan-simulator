## Friction points + resolutions

1. **`LAG()` rejects GEOGRAPHY.** `IS_TELEPORT` in `VW_TRIP_GPS_POINTS` tried `LAG(POINT_GEOM)`. Fix: `LAG(ST_X(...))`/`LAG(ST_Y(...))` then `ST_MAKEPOINT`. Resolution applied to data-model.yaml source first, regenerated, then live. *Prevention:* note in generator authoring guidance that window funcs can't take GEOGRAPHY - LAG scalars and reconstruct.

2. **Stale live dwell pack.** The account was missing `FLEET_APP.DWELL.VW_VEHICLE_TELEMETRY` (present in current generated setup.sql but never installed on this account). New views `dwell_trips`/`dwell_live` depend on it. Resolution: synced the view live from setup.sql. *Prevention:* a "pack drift" check (compare installed FLEET_APP objects vs generated setup.sql) before building views on a pack; or re-run install.py for the pack.

3. **ORS verbs unverifiable - all ORS services SUSPENDED.** `ISOCHRONES` returned empty geometry. This blocked the ORS-dependent Phase 3 overlays (isochrone catchment, reachability, VRP). Resolution: shipped only the non-ORS Phase 3 pieces (density via VW_REGIONAL_ADDRESSES, AI rationale via CORTEX.COMPLETE); deferred ORS verbs. *Prevention:* ORS-verb views need an `/api/tool` route with region-resolution + ORS-readiness (mirroring the control app); declarative SELECT layers silently render empty when ORS is idle (anti-pattern). Document as a follow-on.

4. **Config-only redeploy is fast.** `SKIP_IMAGE=1` re-uploads app-views.json (stage-mounted) + rotates service in ~1 min - good for JSON-only iterations that don't touch the renderer.
