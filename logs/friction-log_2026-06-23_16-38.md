## Friction Points

### F1: Persistent zsh shell wedged in quote-continuation (`dquote>`) on inlined multi-line module loop

- **Step:** 6 (Deploy app)
- **Severity:** Medium
- **What happened:** Running the documented 9-module `for ... do bash run_sql_module.sh ... done` loop as an inlined multi-line command through the bash tool left the persistent shell stuck at a `dquote>` (and then `quote>`) continuation prompt. Subsequent commands were swallowed by the open quote state; several attempts to close the quote re-opened it because of how the tool wraps input.
- **Resolution:** Recovered the shell by submitting a single empty line, then wrote the loop to `/tmp/run_modules.sh` and launched it as a single-line `nohup bash /tmp/run_modules.sh > /tmp/modules.log 2>&1 &`. All 9 modules then ran cleanly (ALL_MODULES_DONE, no SQL errors).
- **Recommendation:** The SKILL.md Step 6 snippet shows a multi-line `for` loop. For agents driving a persistent shell, recommend writing that loop to a temp `.sh` file and invoking it as a single-line command (or chaining modules with `&&` on one physical line). Add a note: "Do not paste the multi-line for-loop directly into a persistent shell — write it to a script file first."
